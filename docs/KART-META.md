# KART-META — 哪一台車跑哪一張圖最快、賽季旗艦

2026-11-21，`feat/kart-meta-flagship`。擁有者原話：「這遊戲能不能做到像跑跑這樣，幾乎有一台車是公定最快的車，比如一個時代是……一個時代是……，我們的這款哪一台車玩哪一個地圖最快？最好有分上下坡，有些賽道急彎多可能要操控好加速快，有些可能急速要快？」（原作車名不用：`CLAUDE.md` 規則 1、`IP-CHECKLIST.md`。）

做成兩層：

1. **賽道特性決定最快車**（§1、§2）：物理讓重量影響坡道，每張賽道算出自己的特性，用同一雙手開 20 台車 × 12 張內建賽道找出每張圖的前三名。車庫與賽道選單顯示「這張圖最快」。
2. **第一季旗艦**（§3）：一台原創、整體公認最快、但難開的車——**黑鳶／Black Kite**（`kite`，2026-11-22 定案），新的等級「賽季旗艦」。

重量：`npm run kart:meta`（`-- --who master|expert|novice`、`-- --seeds 9`、`-- --jobs 6`、`-- --save x.json`、`-- --load a.json,b.json`；六個 job 全表約 4 分鐘）。純邏輯在 `scripts/kart/meta.ts`，測試 `tests/kart/meta.test.ts`、`tests/kart/flagship.test.ts`、`tests/kart/slopeWeight.test.ts`；車庫讀的靜態結果在 `shared/kart/meta.ts`。

**2026-11-23 補跑四張有高台的圖**（`npm run kart:meta -- --tracks wharf,works,danhai,breakwater`，頂尖腳本會上高台，九個種子中位數；`KART-FEEL.md` §25）：前三名**三張都換了**。碼頭倉庫 阿給／寄居蟹／招潮蟹 → **蝦蛄／旗魚／水獺**（招潮蟹掉到最慢 +10.4%：重、極速低，上坡助跑後到不了 63.4 m/s 的門檻）；高架廠區 海豚／鵜鶘／魟魚 → **海豚／水獺／雨燕**；淡海夜城 阿給／白鷺／渡輪 → **海豚／鵜鶘／魟魚**（白鷺在這張反而最慢 +26%：極速最高但轉向 −2，夜城的直角接跳台對不準，常常偏出牆的一端，照實寫）；新圖防波堤屋頂第一名是**白鷺**（速度 +2，三座高台門檻 60–66 m/s，極速型最容易上去），旗艦黑鳶只快 0.44%。結論：高台讓「極速＋上坡不掉速」的車在需要直線助跑的圖變強，但起跳要斜著對準，轉向太差的極速車在助跑短的圖會吃虧。

**2026-11-22 補跑竹圍高架**（`npm run kart:meta -- --tracks zhuwei`，九個種子中位數）：急彎只有 1.4／km、兩條 264 m 的臂，是極速圖，白鷺領先 2.5%；這張不改下面 12 張的統計，白鷺第一的張數變 5／13，仍不超過一半（`fairness`）。

**旗艦以外，每台車拿下的第一名**：白鷺 `heron` 4（漁港、淡江、老街、紅樹林）、海豚 `dolphin` 3（大屯、山城、廠區）、彗星 `comet` 2（淡海、碼頭）、蝦蛄 `shrimp`、虎頭蜂 `hornet`、海燕 `petrel` 各 1。**沒有一台在超過一半的賽道最快**（`fairness` 規則，測試擋）；旗艦以外最慢的平均落後 3.1 秒（招潮蟹）、最快的 1.25 秒（白鷺），一場約 2%。

**為什麼是它們**（讀表的方法：看贏家的數值，對照 §1 的特性）：

- **直線長、急彎少的高速圖 → 極速型**：漁港、淡江（最長直線 377 m）、老街（直線 37%）都是白鷺（極速 +2）第一，旗魚、海豚（極速 +1）緊跟。極速每 1% 約值一場 0.3 秒，在這些圖上大部分時間都是全速或噴射中。
- **急彎多、低速出彎的技術圖 → 加速型**：淡海（急彎 7.9／km、全場最平的技術圖）彗星（加速 +2、操控 +1）第一；紅樹林雖然直線只有 17%，但它的彎是長的高速甩尾，所以還是白鷺，第二是彈塗魚（加速 +2）。
- **陡上坡 → 輕車**：觀音山（上坡平均 11%，比下坡陡）第一是全場最輕的海燕（摩托車、重量 −2），第三雨燕（摩托車）；砲台（上坡 6.1%、下坡 4.1%）第一是虎頭蜂（摩托車），第二是輕的彗星。
- **陡下坡 → 重車**：碼頭（跳台前後的陡坡，下坡那邊 33%）第二、第三是寄居蟹與招潮蟹（重量 +1、+2），第一是彗星（倉庫巷的髮夾要加速）。
- **平衡的長賽道 → 平衡型**：大屯、山城、廠區都是海豚第一——沒有短板、極速 +1，在什麼都有一點的圖上最穩。

**坡道重量做了什麼**（§4）：把重量效果關掉（`slopeMass` 0）再跑一次有坡的八張，觀音山的第一名會從海燕變回白鷺、砲台從虎頭蜂變回彗星、碼頭從彗星變成水獺而重車掉出前二；也就是說重量**改變了三張坡道圖的贏家**，方向都是「陡上坡輕車、陡下坡重車」。河畔與山城的效果小於種子間的差距（河畔的下坡雖然比較陡，重車反而慢了 0.8%，原因沒有拆開量；在這個噪音下也可能只是路線的小差別被放大），不硬說它們是坡道圖，車庫的特性標籤照路面寫。

**2026-11-22（`harbour@15`、`oldstreet@11`：台階與燈籠巷，`KART-FEEL.md` §23）**：兩張在 #145 的物理之後重跑（`npm run kart:meta -- --tracks harbour,oldstreet`）：漁港旗魚、雨燕、虎頭蜂，老街海豚、旗魚、電鰻（白鷺掉出前三）；黑鳶兩張都第一（快 1.9%、1.7%）。白鷺的第一名剩淡江與紅樹林；下面 §2.2 的漁港與老街兩欄是之前的數字。

**2026-11-22（`harbour@13`，會動的障礙物）**：漁港多了兩台滑動貨櫃與一組平交道（`KART-FEEL.md` §20），只重跑這一張（`npm run kart:meta -- --tracks harbour`）：第一名從白鷺變成虎頭蜂（白鷺第三），黑鳶從第一（快 3.4%）變成第二（慢 0.3%）。白鷺的第一名剩 3 張、虎頭蜂 2 張；下面 §2.2 的漁港一欄是之前的數字。

## 3. 第一季旗艦：黑鳶／Black Kite（`kite`）

造型、數值、賽季的資料結構在 `KART-WORLD.md` §4.4。這裡是怎麼調出來、量到什麼。

**目標**（擁有者 2026-11-22 定案，見 §3.1 最後）：對每張圖最快的非旗艦車，頂尖腳本**平均領先 ≤ 1%、單張最多 3.5%**，多數賽道第一；代價是難開；新手開不一定快。（原本的規劃是「差距 1–2%」，2026-11-22 曾要「每張 ≤ 2.5%」，做不到，改成這個。）

**數值**：極速 +2、加速 +2、操控 0、集氣 +2、重量 0（超出預算 +6），極速再 ×1.015（2026-11-22 改過，見 §3.1）；代價 `FLAGSHIP_TRAITS`：`steerResponse` ×2.2、`turnRate` ×1.08、`driftRecoverRate` ×0.8、`wallImpactLoss` ×1.6、`wallScrapeDrag` ×1.5、`wallGaugeKeep` ×0.4；2026-11-22 加 `wallSlideAngle` ×0.5（貼牆滑行只到 6°，`KART-FEEL.md` §22：不這樣漁港領先會變 4.5%）。

**調的過程**（九種組合，每種頂尖 9 場、新手 5–9 場）：

1. 一開始的代價是「甩尾容易甩過頭」（`driftSlip`、`driftSlipIn` 更深更快）與「抓地轉向更磨速」（`gripScrub`）：頂尖腳本反而慢 4%，廠區慢 21%（甩過頭撞進岔路的牆）——這兩個傷高手也傷新手，拿掉。
2. 只加數值不加代價（+4 點）：頂尖腳本只在少數圖第一，差距被種子噪音蓋過。旗艦要在 20 台裡穩定第一，**自身要快 3–4%**（20 台裡最快的那台本來就占了噪音的便宜）。
3. 「轉向跟手」（`steerResponse`）對頂尖腳本是優點（手穩，越跟手越好）、對新手是缺點（手抖會直接傳到車上），撞牆代價也幾乎只罰新手（頂尖腳本很少撞牆）：留下。
4. 把加速點數換成極速（起步慢、極速高）新手會更慢，但頂尖腳本只剩 7／12；最後選 §3 的組合。

**為什麼新手還是比中位數快 2.7%**：新手一場的時間多半花在自己的失誤上（比高手慢 50–80%），旗艦多出來的加速與集氣也幫了失誤後的恢復。所以說法是「**不一定快**」：新手開它只有 3 張圖是最快的車，觀音山與山城排到第 10、11 名，不如開入門的雨燕或寄居蟹。

### 3.1 2026-11-22：把漁港的 6.1% 壓下來（`feat/kart-names-bots`）

擁有者：黑鳶在漁港比最快的非旗艦車快 6.1%，超過目標 1–2%；要每張圖對最快非旗艦車的頂尖腳本差距 ≤ 2.5%、整體仍是多數圖第一、新手開仍不一定快。

**原因**（`measure` 一場一場看）：頂尖腳本開黑鳶在漁港三圈只擦撞牆 2–3 次，白鷺 8–16 次、虎頭蜂 4–6 次。四連髮夾的地方，「轉向跟手 2.2 倍＋轉向率 +8%」讓精準的手幾乎不擦牆——原本設計成懲罰新手的代價，對精準的手反而是優點。

**改了什麼**（`FLAGSHIP_TRAITS`，數值點數不動）：轉向率 ×1.08 → ×1.005、轉向跟手 2.2 → 2.11、極速 ×1.015 → ×1.009（仍是全場最高，白鷺 +2%、它 +2.9%）、加速 ×0.964、甩尾磨速 ×1.07、甩尾放開回正 ×0.8 → ×0.86；撞牆三項不動。

**量到的**（`npm run kart:meta`，九個種子中位數，全部 21 台）：漁港 6.1% → **3.45%**；八張第一（老街 3.37%、山城 2.67%、廠區 2.56%、砲台 1.5%、紅樹林 1.1%、碼頭 0.2%、淡海 0.1%）；四張不是第一（河畔慢 0.8%、淡江慢 2.7%、觀音山慢 1.3%、大屯慢 1.1%）；平均快 0.8%。新手腳本 0／12 張第一、平均慢 3.4%。其他 20 台的時間與前三名完全沒變（只動了旗艦的參數），`shared/kart/meta.ts` 的 podium 不用改。

**照實說：「每張圖 ≤ 2.5%」沒有完全做到**。漁港、老街還在 3.4%，山城、廠區 2.6–2.7%。試了約 230 組參數（極速、轉向率、轉向跟手、加速、甩尾回正、甩尾磨速、抓地磨速、高速轉向損失、噴射時間、重量），每組都跑十二張、九個種子：頂尖腳本對參數非常敏感（換一點點，某張圖的跑線就整個變），**黑鳶在各圖的領先差一直散在 ±3% 左右**。所以「每張 ≤ 2.5%」和「多數圖第一」同時成立的組合沒有找到：

| 試過的方向 | 最大領先 | 第一的張數 | 平均 |
| --- | --- | --- | --- |
| 原本 | 6.1%（漁港） | 10 | 快 1.4% |
| **選用** | 3.45%（漁港） | **8** | 快 0.8% |
| 最大領先最小、又有一半第一 | 2.99%（老街） | 6 | 慢 0.1% |
| 每張都 ≤ 2.5% 的最好一組 | 1.86% | 4 | 慢 1.9% |
| 拿掉「轉向跟手」優勢（2.2 → 1.2） | 1.86–3.5% | 3–5 | 慢 0.7–1.9% |

要每張 ≤ 2.5%，黑鳶就得平均比最快的車慢，就不是旗艦了；所以選了「最大 3.45%、八張第一、平均快 0.8%」。

**定案（擁有者 2026-11-22「全照建議」）**：目標改成「對每張圖最快的非旗艦車，頂尖腳本**平均領先 ≤ 1%、單張最多 3.5%**」，上面這組數值（最大 3.45%、8／12 第一、平均快 0.8%、新手 0／12）照現在定案，不再調。`tests/kart/flagship.test.ts` 擋漁港與老街（領先最大的兩張）≤ 3.5%；平均那一項要跑全部 21 台，看 `npm run kart:meta`。

**伺服器**：`speedCapFor('kite')` 讀它自己的參數，所以速度上限自動跟著它較高的極速（`flagship.test.ts`）；車款編碼是第 21 號（5 bit 車可到 32 台）。電腦車與多人房的電腦車都從 `KART_IDS` 抽，可能抽到它。

## 4. 物理：重量與坡道（`shared/kart/terrain.ts`）

原本坡道只看坡度：極速 ×(1 − 0.5·坡度)（上下限 ±12%）、沿坡重力 9 m/s² × 坡度，**和重量無關**。現在多一項 `slopeWeight`：

- 坡度超過 `slopeMassGrade`（3%）的部分，極速再變動 `slopeMass`（5）×（質量 − 1）× 超過的坡度，上限 `slopeMassMax`（±6%）。重車（質量 > 1）陡上坡更慢、陡下坡更快；輕車相反。質量就是碰撞用的 `kartMass`（重量點數 ×8%、摩托車 ×0.8），由 `applyKart` 放進參數的 `mass`（標準重量不放）。
- **為什麼只算陡的部分**：一圈閉合，爬升＝下降。效果如果只跟坡度成正比，整圈加起來每張圖都抵銷（重車在上坡輸的，下坡全部贏回來），沒有一張圖會偏好重車或輕車。只算陡的部分，才會變成「陡的那邊是上坡 → 輕車占便宜；陡的那邊是下坡 → 重車占便宜」。
- **平地與標準重量完全不變**：`mass` 沒有或等於 1 時 `slopeWeight` 是 0，平面賽道根本不走 terrain，所以 `flatGolden`、`branchGolden` 的雜湊都沒變（標準車 `tide`），賽道 `revision` 不用 +1。有坡賽道上非標準重量的車，時間會差一點點（§2 量到 ±1% 以內）。
- **加速與極速**：沒有另外改。經典手感的引擎本來就是 a = 加速 ×（1 − 拖曳），低速推力最大、接近極速時趨近 0，所以加速點數的價值本來就集中在低速出彎與撞牆後，極速點數的價值集中在長直線與噴射（噴射是極速的倍數）。§2 的結果（技術圖加速型、直線圖極速型）就是這個曲線量出來的。

## 5. 車庫與賽道選單的推薦（`shared/kart/meta.ts`）

- **靜態資料**：每張內建賽道的前三名（旗艦另列）與特性標籤（技術型／高速型／陡上坡／陡下坡／平地）。**車款或物理改了就重跑** `npm run kart:meta`，把印出的 podium 貼回 `shared/kart/meta.ts` 與本文件。測試只擋形狀（三台不同、不是旗艦、有特性、平地的爬升是 0、沒有一台在超過一半的圖第一），不跑比賽。
- **車庫**（`RosterPicker` 的 `track`；`/kart` 的車庫傳目前的賽道、多人等待室傳房間的賽道）：上方「這張圖最快」：特性標籤、三台車（按了就選）、「不算賽季旗艦」；車卡片多「推薦」、選中時多一個「這張圖推薦」標籤。
- **賽道選單**：`/kart` 的賽道下拉旁、對電腦的設定面板的賽道下，各一行「這張圖最快：A · B · C」。
- 自訂賽道、測試橢圓沒有推薦。

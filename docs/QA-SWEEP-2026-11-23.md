記憶體是這台機器的瓶頸：一次只開一個 dev server、一個 worker、一批跑完再下一批。

```bash
npx wrangler d1 migrations apply DB --local --config wrangler.jsonc
E2E_PORT=9901 npx playwright test kart-spike --workers=1               # 一批（約 9 分鐘）
SWEEP_PORT=9903 SWEEP_SCREENS=desktop npm run test:sweep               # 桌遊巡檢，一種畫面一批
npx vitest run --maxWorkers=2
```

## 修了什麼（各有測試）

1. **`/kart?bots` 偶爾開不出「跟電腦比賽」面板**（`src/kart/bots/KartPlay.tsx`）。大廳「跟電腦玩 → 卡丁車」走 `/kart?bots`；`botsAsked()` 在 `useState` 的初始函式裡讀網址**並且當場把 `bots` 拿掉**。第一次繪製若遇到還在下載的 lazy chunk（冷載入、慢網路）而暫停，React 會丟掉這次繪製、連同 state 初始函式重跑一次——第二次網址裡已經沒有 `bots`，面板就不開。Android 412 每次都中、本機 dev 偶爾中（看 chunk 有沒有快取）。改成繪製時只讀，畫面出來後（effect）才把 `bots` 從網址拿掉。測試：`tests/kart/kartPlayBots.test.tsx`（模擬第一次繪製暫停；改之前失敗）；`e2e/phones.spec.ts` Android 412。
2. **大廳鍵盤：第一個「建立房間」要按 47 次 Tab**（`src/pages/HomePage.tsx`）。#158 讓 11 款桌遊都能跟電腦玩，「跟電腦玩」變成三十幾顆按鈕，全都在遊戲列表前面。加「跳到遊戲列表」略過連結（WCAG 2.4.1；有焦點才看得到），按下後焦點到遊戲區；`lobby.skipToGames` 兩語。測試：`e2e/keyboard.spec.ts` 三支改成照鍵盤使用者的路徑走略過連結（12 次 Tab 內到得了，之後 3 次內到「建立房間」）。
3. **陞官圖對局中有兩顆「Full screen」**（`src/pages/RoomPage.tsx`）。#148 在每個房間標題列放了全螢幕鈕（整頁全螢幕），陞官圖圖版自己本來就有「Full screen」（圖版＋擲骰的沉浸模式，#29）；兩顆同名、做不同的事，報讀器與 `promotion-fit` 的 5 支測試都分不出來。陞官圖**對局中**標題列那顆讓位（等待室照常有）。測試：`e2e/promotion-fit.spec.ts`「full screen covers the screen…」多檢查畫面上只有一顆、且不是標題列那顆；`e2e/fullscreen.spec.ts`（等待室）照過。
4. **卡丁車效能回報偶爾 400**（`src/kart/spikeLoop.ts`）。整合情境裡房主頁面的 `POST /api/telemetry` 回 400：載入時間用第一幀 rAF 的時間戳減開始時間，第一幀若就在開始的那一幀裡，時間戳是那一幀的起點、比開始早一點，得到負數，伺服器拒收。改成不小於 0。沒有另寫測試（伺服器的 `parseTelemetry` 已有拒收負數的測試）。

過時的測試預期：`e2e/quick-play.spec.ts` 的「9 ways」改成按 `[data-quick-toggle]`（數字會跟著能跟電腦玩的遊戲變）。

## 沒修、交給別的分支

- **手機橫拿時駕訓班邀請被頂列連結蓋住**（`src/kart/SpikePage.tsx` 的 `Invite`，`max-height: 500px`）。第一次開 `/kart`、沒回答過邀請時，橫拿手機上邀請在畫面頂端正中，頂列連結自從多了「開啟重播檔」（#161）和「線上對戰」（#163）就長過中線，蓋掉邀請第一行（Android 915×412、667×375 都看得到）。試過把邀請移到頂列下方，結果蓋到左撇子配置的圈數框、也擋到觸控 e2e 點畫面中間的位置（4 支觸控測試失敗），**已撤回**。要好好擺得一起看頂列、左右 HUD 與左撇子配置，交給卡丁車介面（`feat/kart-*`）；簡單的做法是橫拿時把頂列連結收進「選單」，或邀請改成底部一條。

- **陞官圖完整版在 844×390 手機橫拿、非專注模式：圖版底部 28 格（共 236）在畫面外**（`e2e/promotion-full.spec.ts`「at 844x390 nothing moves over many rolls」）。圖版的可用高度＝畫面高 − 圖版上緣 − 下方操作列，算出來小於下限 240 px（`useBoardFit.ts` `MIN_STAGE`）就照 240 畫，於是超出畫面。上緣被頂到約 235 px：頂列＋房間標題列（#155 的直播狀態牌）＋座位列。專注模式那支過。這是牌桌與房間標題列的版面，和 `feat/boardgame-table-esports` 正在改的同一塊，沒在這裡動；建議短螢幕（`max-height: 500px`）把標題列與座位列縮成一行，或對局中預設專注模式。

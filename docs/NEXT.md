## 3. 工作方式（每批）

1. **在 worktree 開分支**：`git worktree add ../_wt/<分支> -b feat/<第一個 task 編號>-<slug>`。
2. **只讀需要的段落**：`CLAUDE.md`、這份、`ROADMAP.md` 的該批、該批 task 所在的 epic 段落、相關的 `ARCHITECTURE.md` 章節。不要整本讀；歷史檔只用搜尋。
3. **做完跑** `npm run lint && npm run typecheck && npm test && npm run build`，只看最後 5 行。動到前端的批次再跑 `npm run budget -- --chunks`，把每條首屏線的 bytes 寫進 PR（D4 的規則）。介面字串改了跑 `npm run check-i18n`。
4. **一批一個 ready PR**：標題英文、結尾列出全部 task 編號；本文（繁中）寫對應 AC、怎麼驗證、實測結果（卡丁車多人要兩台裝置）。
5. **在同一個 PR 更新文件**：epic 勾選 task（寫 PR 號）、AC 勾選（有驗證才勾）、`PRD/README.md` 進度表、`ROADMAP.md` 該批 `[x]` 與 PR 號（路線圖外的在表尾加一列）、這份 §1 加一兩行、§5 刪掉做掉的、新的已知限制加進 §5。
6. **CI 綠了直接合併**（`gh pr merge --squash --delete-branch`），需要人決定的事才停下來問（加進 §2.1）。

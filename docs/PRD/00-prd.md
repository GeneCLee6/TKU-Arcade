# PRD — TKU Arcade · 淡江遊樂場

> 這是產品的總 PRD：願景、範圍、功能需求（F）、驗收條件總表、里程碑與風險。每個 epic 的細節、AC 與 task 拆分在同一個資料夾的 `e*.md`，**勾選狀態以 epic 文件為準**。資料夾的閱讀方式與 task 格式見 [`README.md`](README.md)，版權與法律判斷見 [`01-legal-ip-analysis.md`](01-legal-ip-analysis.md)，為什麼只分三層見 [`../PLANNING-METHOD.md`](../PLANNING-METHOD.md)。
>
> **名稱已拍板（2026-11-03）**：TKU Arcade，中文副名「淡江遊樂場」只在繁中介面出現（§14 Q1）。介面預設英文、依瀏覽器語言自動切繁中（§14 Q1b）。

## 1. 願景

**一個開給社團朋友的遊戲大廳：進來、選一款、一起玩。** 先用派對桌遊把「貼連結就能一起玩」做穩，最後把朋友圈最懷念的卡丁車做成自己的版本。

- **M0 能開桌（大廳 MVP）**：大廳、暱稱進場、建房／加入房、第一款遊戲「升官圖」（公有領域、規則簡單、擲骰就能玩）、房內聊天、英文／繁中雙語。
- **M1 派對桌遊三款**：默契牌局（合作撲克）、光譜猜題（腦洞量表風格）、真假朗讀（瞎掰王風格）；共用一套「遊戲框架」（房間、回合、計分、旁觀、重連）。
- **M2 卡丁車單機**：瀏覽器裡的 3D 卡丁車，甩尾加速（drift boost）手感對齊記憶中的跑跑卡丁車；一張賽道、時間賽、幽靈車。
- **M3 卡丁車多人**：同房 2–8 人線上競速、道具賽、排名；第二、三張賽道；自製角色與車。
- **M4 社群與打磨**：好友、成就、排行榜、賽季、更多桌遊（投票決定）。

基本原則：**玩法可以學，資產不能抄**（§13 法律風險與 `01-legal-ip-analysis.md`）。所有名稱、角色、美術、音樂、題目卡文字都是自己的；只有「規則與手感」來自原作。

## 2. 背景與問題

- 淡江橋藝社已經有兩個站：淡江牌桌（`C:\dev\TKU-BridgeTable`，線上橋牌）與淡江橋館（`C:\dev\TKU-BridgeHall`，制度手冊）。社團聚會不是只打橋牌，常常想「隨便玩個派對遊戲」，但現成的線上桌遊平台要帳號、要付費、沒有繁中、或根本沒有想玩的那幾款。
- 擁有者最想要的是**跑跑卡丁車**：台服 2023 年 1 月關閉、續作《飄移》2025 年也宣布停服（[TVBS](https://cars.tvbs.com.tw/car-news/83527)、[4Gamers](https://www.4gamers.com.tw/news/detail/72434/kartrider-drift-nexon-shut-down)），沒有合法的地方可以再玩。想做一個「自己和朋友玩」的版本，玩到以前沒玩到的後面車款的感覺。
- 開發者已有 React＋TypeScript＋Cloudflare Workers／Durable Objects 的即時多人經驗（牌桌的 WebSocket 牌桌、LongTalk 的房間），桌遊部分可以直接沿用；3D 與即時物理是新題目，所以排在 M2 之後，先把地基用桌遊打穩。
- 這個站**不營利**、不投廣告、不收費、不開放給陌生人，但網站是公開連結（朋友不用帳號也能進）。這一點決定了法律判斷：非營利不等於沒有版權問題，見 §13。

## 3. 目標與非目標

**目標**

1. 任何人拿到連結，10 秒內進到房間、看得到其他人；不用註冊、不用安裝。（M0）
2. 遊戲框架一次做好：新加一款桌遊只要寫「規則模組＋畫面」，不用再碰房間、聊天、重連、旁觀、計分板。（M0–M1）
3. 四款桌遊的規則由伺服器判定，前端只呈現；斷線重連回到同一局；旁觀者看得到局面但看不到手牌。（M0–M1）
4. 介面預設 English，可切繁體中文（台灣用語）；每一句介面文字都有兩種語言。（M0）
5. 卡丁車的甩尾手感要「像」：接近原作的 drift → 加速條 → boost 節奏，先做單機時間賽，自己覺得順了才做多人。（M2）
6. 2–8 人線上競速，延遲 100 ms 內看起來順、道具命中由伺服器裁定。（M3）
7. 一切名稱、角色、賽道、美術、音效、題目卡都是原創或授權可用（CC0／CC BY）；上線前有一份檢查清單。（全程）
8. 全程維持 Cloudflare 免費額度；3D 資產走 R2 與快取。（全程）

**非目標**

- 商業營運、廣告、課金、對外公開招募玩家。
- 複製原作的角色（皮蛋、Dao、Bazzi 等）、車款名稱、賽道、音樂、介面圖像；使用「跑跑卡丁車」「KartRider」作為名稱或宣傳。
- 原生手機 App（PWA 即可；卡丁車以桌機鍵盤／手把為主，手機觸控是 M4 選用）。
- 複雜的桌遊（策略類、超過 60 分鐘）；一款桌遊的規則若超過兩頁就不在前三波。
- 反作弊到競技等級：這是朋友圈，伺服器裁定夠用。
- 匯入牌桌的橋牌功能；橋牌留在淡江牌桌。

| 玩家（朋友） | 點連結、取暱稱、選房、看規則摘要、玩、聊天、看結果 |

| 維護者（擁有者） | 看得到哪款遊戲有人玩、房間數、成本；能下架一款遊戲 |

## 5. 產品原則

1. **連結就是入口**：一個網址 = 一間房；暱稱就能玩；帳號是加分不是門檻。
2. **規則在伺服器**：誰的回合、誰得分、誰撞到道具，由 Durable Object 判定；前端只呈現。
3. **遊戲是插件**：每款遊戲實作同一個 `GameModule` 介面（`shared/games/<id>/`），大廳不知道遊戲內容。
4. **先手感，後內容**：卡丁車先把一張賽道的甩尾做到自己滿意，再做第二張。
5. **自己的世界**：原創的名稱、角色、美術；玩法致敬，資產不抄。
6. **English first, 繁中並列**：字串表以英文為 key 的來源語言，繁中是翻譯；缺翻譯時顯示英文，CI 擋缺漏。

## 9. 非功能需求

- **延遲**：桌遊動作到其他人看到 < 300 ms；卡丁車同房 RTT < 100 ms 時其他車移動看起來連續，RTT 100–250 ms 時以插值掩蓋，> 250 ms 顯示警示。
- **穩定**：一局桌遊中斷率 ≤ 1%；重連 5 秒內回到同一局；RoomDO 在 hibernation 後狀態不遺失。
- **成本**：Cloudflare 免費額度（Workers、DO、D1、R2 10 GB）；3D 資產總量 ≤ 200 MB，走 R2＋Cache；成本儀表板在 E12。
- **效能**：大廳與桌遊頁 JS gzip ≤ 150 kB；卡丁車頁 lazy 載入，three.js 與場景分 chunk，首張賽道資產 ≤ 15 MB；在五年內的筆電內顯晶片 60 fps（有降畫質選項）。
- **相容**：Chrome／Edge 最近兩版、Safari 17+、Firefox 最近兩版；桌遊支援手機瀏覽器；卡丁車桌機為主（手機觸控 M4 選用）。
- **無障礙**：桌遊全部操作可鍵盤完成；狀態不只靠顏色；卡丁車有鍵位重設與色盲友善的道具圖示。
- **安全與隱私**：暱稱不是身分；登入走牌桌的 session；聊天速率限制；不收集超過必要的資料；符合台灣個資法。
- **授權**：每個資產（模型、貼圖、音效、字型）在 `docs/ASSETS.md` 登記來源與授權；CI 擋沒登記的檔案（E12）。

## 13. 風險

| 風險 | 對策 |
| --- | --- |
| **版權與商標**：抄到原作的名稱、角色、美術、題目文字 | 玩法可學、資產不抄（`01-legal-ip-analysis.md`）；E12 AC-12.8 IP 檢查清單；資產一律登記來源；產品與遊戲名稱全部原創；不在任何公開文字用「跑跑卡丁車」「KartRider」或原作桌遊名當作自己的名稱 |
| Nexon 對同人與類似作品積極維權 | 不用原作任何資產；不公開宣傳、不放到遊戲平台；只給朋友連結；若接到通知就下架（E12 功能旗標） |
| 3D 與即時物理是新技術，M2 可能做不出想要的手感 | M2 第一批是 spike：一台方塊車在一塊平地甩尾，先做手感再做內容；調參面板；手感不對就不進 M3 |
| 網路同步做不好，多人卡頓 | 先「客戶端自主、伺服器裁定關鍵事件」的簡單模型（朋友圈不防作弊）；延遲實測是 AC-9.6 |
| 3D 資產產出慢（沒有美術） | 低多邊形風格；Kenney 等 CC0 套件起步；角色與車款數量少；賽道用片段拼接 |
| 一個人做，範圍太大 | M0–M1 全部沿用牌桌的技術與做法；卡丁車每批只做一件事；M4 不先細拆 |
| 題庫寫不出 100 題 | AI 生成草稿＋人工審核（F16）；聚會時收集朋友出的題 |

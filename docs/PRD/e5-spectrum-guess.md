## 背景

每回合抽一個有兩端的題目（例如「宵夜」：1 ＝最不想吃、10 ＝最想吃）。一位玩家當猜題者，其他人各拿到一個 1–10 的祕密數字，用一個東西或一個詞說出「我的數字落在這兩端之間的哪裡」。猜題者看完所有回答，指出誰的數字最大、誰的最小。好玩的地方是同一個題目每個人的尺度不一樣：「鹹酥雞」在你心裡是 9，在他心裡可能只有 6。

玩法和日本的卡牌遊戲 ito（Arclight）相近（原作是合作排序），比舊版參考的 Wavelength 更像。玩法不受著作權保護；名稱、美術、規則說明文字、**每一個題目**都是我們自己的（`01-legal-ip-analysis.md` §2.3）。

線上版的好處：發數字、藏數字、計分、輪替都自動；題庫可以一直加；面對面玩也只要每人一支手機。

## 目標

- M1：4–11 人完整一局；題庫 ≥ 300 題（自寫、擁有者逐題審過才上線；先繁中，英文之後補）；猜最大與最小（預設）與全排序（規則選項）兩種模式；揭曉動畫與計分；題目管理頁與 AI 生成草稿。

## 非目標

- 分隊、對抗賽（舊版設計，已拿掉）。
- 合作模式（大家一起排出順序、不計個人分）：M4 投票再說。
- 語音：回答用打字；面對面玩時嘴巴講也行，但網站只認打字送出的回答。
- 英文題庫：M1 先做繁中；英文介面下題目顯示繁中原文還是隱藏這款遊戲，見未決問題。

## 需求

- **人數**：**4–11 人**（1 位猜題者＋ 3–10 位回答者；2026-11-10 定案）。下限 4 是為了至少 3 位回答者，「最大」與「最小」才是兩個不同的判斷；上限 11 是數字不重複時回答者最多 10 人。
- **回合與角色**：每回合一位猜題者，照座位輪替；其他人是回答者。一局每人當一次猜題者，規則選項可改成兩輪（2026-11-10 定案）。
- **祕密數字**：每位回答者拿到一個 1–10 的整數。**預設不重複**；規則選項「允許重複」打開後，每人獨立抽。
- **題目**：每回合從題庫抽一題，有題目文字與兩端（`low` ＝ 1 那端、`high` ＝ 10 那端）。本房用過的不再出現；房主可選分類。
- **回答**：每位回答者送出**一個**回答（一個東西或一個詞），表達自己的數字在兩端之間的位置。**回答不能含數字**：伺服器擋半形與全形的阿拉伯數字（`0-9`、`０-９`）；國字數字（「一」「十」）會誤傷正常詞（「一般」「十足」），**不擋**（2026-11-10 定案），規則頁寫明不能報數字，靠玩家自律。長度上限 30 字。送出前可以改；全部送出（或倒數到）就鎖定。
- **猜題（預設：猜最大與最小）**：猜題者看到所有回答，選一位「數字最大」、一位「數字最小」（不能選同一人），送出後揭曉。
- **猜題（規則選項：全排序）**：猜題者把所有回答由小排到大，送出後揭曉。
- **揭曉**：所有人的數字一起翻開，回答依數字排在 1–10 的數線上，標出猜對與猜錯。
- **計分（2026-11-10 照提案定案，試玩後再檢討）**：
  - 猜最大與最小：**每猜對一個，猜題者 ＋1、被猜對的那位回答者 ＋1**。一回合猜題者最多 ＋2。允許重複時，數字並列最大（或最小）的任何一位都算對。
  - 全排序：**每位被放在正確位置的回答者，猜題者 ＋1、那位回答者 ＋1**。並列的數字之間怎麼排都算對。
  - 一局結束時總分最高的人勝；同分並列。
- **誰看得到什麼（view）**：
  - 回答者：只看得到**自己的**數字。
  - 猜題者：看不到任何數字。
  - 旁觀者：同猜題者，看不到任何數字。
  - 回答：全部送出（或倒數到）之前，其他人只看得到「誰已作答」；之後所有人看得到所有回答（2026-11-10 定案）。
  - 揭曉：所有人看得到所有數字。
- **題庫**：存 D1 的 `prompts` 表，`game='spectrum'`，`payload` 是 `{ topic, low, high }`；分類（食物、校園、橋牌與遊戲、生活、娛樂、人際、旅行、怪問題、科技、工作、動物與自然）。來源：自寫、朋友投稿、AI 生成草稿；**全部經擁有者審核才上線**；**不搬原作的任何題目**。第一批草稿在 [`../content/spectrum-topics.zh-TW.csv`](../content/spectrum-topics.zh-TW.csv)（335 題，繁中）。
- **題目管理頁**（擁有者）：列表、新增、停用、分類、匯入 CSV（格式同上面的草稿檔）；AI 生成：輸入分類與數量 → 草稿列表 → 人工勾選才上線。

## 設計方向

- 階段：`answering` → `guessing` → `reveal` → 下一回合（或 `ended`）。
- action：`submitAnswer(text)`（回答者，鎖定前可重送覆蓋）、`guessExtremes(maxSeat, minSeat)`（預設模式）、`guessOrder(seats[])`（全排序模式）、`next`（揭曉後由猜題者或房主進下一回合）。`legalActions` 列幾個回答樣本即可，`reduce` 要接受每一個合法字串。
- 發數字：每回合用 `Rng` 洗 1–10（不重複時取前 n 個）；數字只在 state 裡，`view` 只給回答者本人。
- `timers`：作答 90 秒、猜題 60 秒（規則選項可關）。作答時間到還沒送出的人，本回合不參加猜題；猜題時間到算沒猜，零分。
- 缺席：回答者缺席時房主可跳過（本回合不參加）；猜題者缺席時房主可跳過整回合。代打不適用（回答要人寫）。
- 題目取用：RoomDO 開局時從 D1 抓一批（避免每回合查）；用過的題目在本房不重複。
- 題庫表與 E6 共用結構（`prompts`：id、game、kind、payload JSON、lang、category、difficulty、status、source）。
- AI 生成走 Worker 端（金鑰不進前端），沿用牌桌的 Anthropic SDK 用法；總 PRD Q5。生成提示詞不提任何原作名稱。

### H1 定案的規則細節（程式在 `shared/games/spectrum/rules.ts`）

上面沒講清楚、H1 決定的部分。都只動 `rules.ts` 幾行就能改，**試玩後再檢討**：

- **題目來源（暫時）**：F3 之前，題目來自 `docs/content/spectrum-topics.zh-TW.csv`（335 題），用 `node scripts/spectrum-topics.mjs` 產生 `shared/games/spectrum/topics.ts`；`tests/games/spectrum/topics.test.ts` 擋兩邊不一致。題目 id 是 CSV 的第幾題（從 1 起）。這個檔只在 Worker：`tests/games/catalog.test.ts` 會沿著 `src/` 的 import 一路追下去，碰到任何 `rules.ts`、`topics.ts` 或 `index.ts` 就失敗；`dist/client` 也確認沒有題目文字。**F3 要做的**：題目改從 D1 `prompts` 抓（RoomDO 開局抓一批），`topics.ts` 與產生腳本刪掉或改成 seed 來源；房間的 state 只存題目內容與用過的 id，換來源不影響進行中的局。
- **分類選擇**：「房主可選分類」留給 F3（和題庫表一起），H1 沒有這個規則選項：多一個選項就多 12 組首屏字串。
- **第一位猜題者**：開局用 `Rng` 隨機選一個座位，之後每回合往下一個座位輪；一局 `人數 ×（1 或 2）` 回合，所以每人剛好當一次（或兩次）。
- **題目不重複**：本房用過的 id 記在 state 的 `usedTopics`（不送給瀏覽器）。最長一局 11 人兩輪 22 題，遠少於 335 題；萬一用完，題庫從頭再來，不會卡住。
- **回答的檢查**：先把任何空白（含換行、tab）壓成一個空格、去掉控制字元、頭尾修掉，再檢查：空的擋（`empty`）；超過 30 個字擋（`tooLong`，算 Unicode 字元，不算位元組，emoji 一個算一個）；**數字擋 `\p{Nd}` 與 `\p{No}`**，也就是半形、全形與其他文字系統的阿拉伯數字，加上 ①、²、½ 這類「數字符號」，免得用圈圈數字繞過。國字數字（一、十、〇）照定案不擋。
- **鎖定**：最後一位回答者送出的那一刻就鎖定（不用另外按），之後不能改。倒數到時，還沒送出的人這回合「不參加」（`out`）：不在猜題範圍、不得分，但揭曉時他的數字照樣公開。
- **回答不到兩個**（倒數到或房主跳過之後）：沒有東西可比，這回合直接揭曉、不計分（`reveal.missed = 'tooFew'`）。
- **猜題時間到**：算沒猜（`missed = 'time'`），零分，直接揭曉。
- **猜最大與最小**：不能選同一人；只能選這回合有回答的人。允許重複時，數字並列最大（或最小）的任何一位都算對；全部同一個數字時，選哪兩位都是兩個都對。
- **全排序**：要把這回合每個回答剛好排一次。對錯的算法：把真正的數字由小到大排好，第 k 個位置上的人，數字等於第 k 小的數字就算對，所以並列的數字之間怎麼排都對。
- **揭曉後誰按下一回合**：**只有猜題者**（`next`）。模組不知道誰是房主，「房主也能按」做不到；猜題者離線時，房主用代打面板的「跳過」替他按。最後一回合猜完直接結束（`over`），最後的揭曉留在 view 裡，不用再按。
- **缺席**：沒有 `proxyTurns`（回答要人寫）。`skipAction`：作答中、還沒送出的回答者 → 這回合不參加，可能因此鎖定；已送出的回答者沒有可跳過的（回 `null`）；猜題中的猜題者 → 不計分直接揭曉（`missed = 'skipped'`）；揭曉時的猜題者 → 下一回合。作答中的猜題者沒有動作，不會出現在代打面板。
- **倒數**：規則選項 `clock` 預設開（作答 90 秒、猜題 60 秒，照上面的設計方向），可關。計時器 id 帶回合數（`answer-3`、`guess-3`），每回合重新計時；揭曉沒有倒數。時間到由房間送 `timeUp`。
- **`chatLocked`**：作答與猜題時關閉聊天，揭曉與結束時開放。回答者猜對有分，聊天室會變成報數字的管道。
- **計分欄位**：每人 `score`（總分）、`guessed`（當猜題者得的分）、`read`（當回答者被猜對得的分）。`result()` 依總分排名，同分同名次；摘要分「一人最高」與「幾人並列」兩種。
- **view**：作答時，別人的回答只給「誰已作答」（`status`），自己的回答看得到；鎖定之後所有人（含旁觀者）看得到所有回答；數字只有回答者本人看得到自己的，揭曉後全部公開。猜題者與旁觀者的 view 除了 `you` 完全相同（測試擋）。過去回合（`history`）全部公開。`usedTopics` 與 `firstGuesser` 不送。
- **測試怎麼證明沒有洩漏**：除了逐項檢查，還有「換掉看不到的東西，送出的內容一個字都不能變」的測試：在 4、6、11 人、兩種規則組合的隨機整局的每一個位置，對每個觀看者把他不該知道的（別人的數字、鎖定前別人的回答）隨機換掉，再比對序列化後的 projection（含 `legal`）。另外在 PR 預覽站用真的 `RoomDO` 與 WebSocket 跑同樣的檢查。

### H1 的元件（`src/games/spectrum/`，畫面在 H2）

- **`NumberLine`**：揭曉的數線。每個回答放在自己的數字上，由小到大依序浮上來（每個間隔 180 ms，`animate={false}` 或 `prefers-reduced-motion` 時不動）；靠太近的（差不到 3）往上疊一層（`lanes()`），所以 10 個相同數字也不會疊在一起。每個標記有回答、名字、座位色的數字，以及猜題者猜它什麼（最大／最小／排第幾）和對錯（✓✕加文字，不只靠顏色）。整張圖對螢幕閱讀器隱藏，另有一個依序的清單讀出來。只顯示給它的資料，資料由 `revealMarks()` 從揭曉的 view 轉來。
- **`OrderList`**：全排序模式的排序操作。拖曳一列放到另一列上，或用每列的「往 1 那端／往 10 那端」兩個按鈕（鍵盤、手機都能用，44 px）。只管順序，送出 `guessOrder` 是 H2 畫面的事。手機的觸控拖曳沒有做（HTML5 拖放在手機上不動作），手機用按鈕。
- 字串在 `i18n.screen.ts`，元件自己 `registerMessages`（`src/games/spectrum/messages.ts`），不進首屏。

### H2 定案的細節（畫面在 `src/games/spectrum/`）

- **掛法**：`src/games/screens.ts` lazy 載入 `SpectrumScreen.tsx`，和默契牌局一樣；畫面字串全在 `i18n.screen.ts`，首屏只多了主題色。仍是 `meta.unlisted`：要 `POST /api/rooms` `{"gameId":"spectrum"}` 開房、貼網址加入（e2e 也這樣做）。
- **主題色**：`gameSpectrum`，深色 `#4DA3FF`、淺色 `#1D5FC4`（原型的藍），照 E1 的做法放進 `gameHues`，房間頁與規則頁整頁換成藍色。量表、數線、題目兩端都是「主題色 → 洋紅」的漸層（1 那端藍、10 那端洋紅），最大是洋紅、最小是藍。
- **一回合的畫面**：上面是回合數、三步（作答、猜題、揭曉，`aria-current`）與猜題者；禁聊時一行提醒；題目卡（分類斜標籤、大字題目、1 與 10 兩端）；然後依階段：
  - 作答：回答者是「祕密數字卡（大字、1–10 量表、偏哪一端的提示、藏起來按鈕）＋回答表單」；猜題者是「這回合你是猜題者」說明；大家都有作答進度（誰想回答中、誰已作答，**不給內容**）。
  - 猜題：所有回答一人一張卡；猜題者每張卡有「最小」「最大」兩個按鈕（`aria-pressed`，同一張不能兩個都按，再按一次取消），dock 裡的「確定」選滿才能按；全排序模式用 `OrderList`。其他人看到同樣的卡（沒按鈕）、「誰正在猜」，回答者另有一行自己的數字（可藏）。
  - 揭曉：`NumberLine`（看著它出現時才逐一浮上來，重新連線或開頁時已經揭曉就直接顯示）、每個猜的對錯（✓✕加文字）、這回合誰得幾分；沒猜的原因（不到兩個回答、時間到、被跳過）。「下一回合」只有猜題者有，其他人看到「等誰開始下一回合」。
  - 計分板一直在最下面：總分高到低、猜題者標籤、揭曉時的 `+n`。房間的成員列也顯示每人的分數。
  - 結算用共用的 `ResultPanel`（`result()` 的摘要與「當猜題者 n 分、當回答者 n 分」）。最後一回合的揭曉在動畫跑完才出結算（`resultHeld`）。

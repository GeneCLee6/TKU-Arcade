# docs/PRD — 怎麼讀、怎麼用

這個資料夾是產品需求的唯一來源。結構與淡江牌桌、淡江橋館、LongTalk 相同（為什麼只分三層：[`../PLANNING-METHOD.md`](../PLANNING-METHOD.md)）。

```
00-prd.md                  總 PRD：願景、範圍、F 需求、AC 總表、里程碑、風險、未決問題
01-legal-ip-analysis.md    版權與智慧財產：哪些能做、哪些不能（法律風險，獨立一份）
e1 … e12                   epic：背景、目標、非目標、需求、設計方向、AC、task、風險、未決問題
../ROADMAP.md              批次順序（一批 = 一個 PR = 一個 AI session）
../NEXT.md                 現在的位置與每批的工作方式
../ARCHITECTURE.md         技術架構（Worker、DO、GameModule、卡丁車同步）
../DESIGN.md               設計規格與 i18n 規則
```

## 讀的順序

| 情境 | 讀 |
| --- | --- |
| 第一次看這個專案 | `00-prd.md` §1–§7，然後 `01-legal-ip-analysis.md` §4 |
| 開工做某一批 | `../NEXT.md` → `../ROADMAP.md` 的該批 → 該批 task 所在的 epic 段落 |
| 想知道某個功能做到哪 | 該 epic 的 AC 勾選 → 下面的進度表 |
| 加一款新桌遊 | `e2`（GameModule）＋ 任一款桌遊 epic 當範本 |
| 版權疑問 | `01-legal-ip-analysis.md` |

## Task 格式

```
- [ ] `e<epic>-t<nn>` 一句話說明 · AC-<epic>.<n> · S|M|L · ← 前提 task
```

- `S` ≈ 半天、`M` ≈ 1–2 天、`L` ≈ 3 天以上（L 要拆）。
- 做完改 `[x]` 並在句尾寫 PR 號（`#12`）。
- AC 有驗證（測試或實測）才勾。

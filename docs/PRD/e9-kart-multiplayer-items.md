## 背景

單機手感對了（E8 AC-8.8 簽核）之後，才做多人。目標是朋友圈 2–8 人同房競速與道具賽，不是競技等級的反作弊。所以採最簡單可行的模型：**每台車由自己的客戶端模擬，伺服器（RoomDO）轉送狀態並裁定關鍵事件**（圈數、名次、道具命中）。這和牌桌「狀態只在伺服器」的原則不同，是刻意的取捨：即時物理在 DO 上跑 60 Hz 對免費額度與延遲都不划算；朋友圈不需要防作弊。

## 目標

- M3：同步協定、插值、道具賽（6–8 種原創道具）、競速房（併入 E1 房間）、結果與排名、觀戰、延遲實測紀錄。

## 非目標

- 伺服器權威的完整物理回滾（rollback netcode）。
- 反作弊、排位配對。
- 超過 8 人。

## 需求

- **同步協定**（`shared/kart/net.ts`，在 E2 協定 v1 之上加 `kart.*` 二進位訊息）：
  - 客戶端：60 Hz 模擬自己的車；每 50 ms（20 Hz）送 `state`（tick、位置、朝向、速度、甩尾狀態、加速條、噴射）與最近輸入。
  - RoomDO：收到即廣播給其他人（不重新模擬）；維護每台車的「最後已知狀態」與檢查點進度；裁定圈數、名次、完賽；alarm 驅動起跑倒數與超時。
  - 其他車：以 100 ms 緩衝做插值；缺包時外推（dead reckoning）≤ 200 ms；超過顯示「連線不穩」。
  - 訊息用 `ArrayBuffer`（DataView）而不是 JSON，一個 state ≤ 40 bytes。
- **車對車碰撞**：各自在本機算（推開＋小減速），不同步結果（可接受的小不一致）。
- **道具賽**：道具箱位置在賽道 JSON；拿到由伺服器裁定（先到先得，客戶端只送 `pickup(boxId, tick)`）；隨機給道具（名次越後越好的道具，表格可調）；使用 `use(itemId, tick, aim)` 送伺服器；**命中由伺服器裁定**（用最後已知狀態＋簡單幾何）；效果廣播，被命中者本機套用效果（打滑、停頓、減速）。
  - 原創道具草案（名稱與外觀拍板時定）：加速、追蹤飛彈（打前一名）、護盾、地面陷阱、磁鐵（拉近前車）、水彈（視線）、全體減速（最後一名限定）、瞬移（換位）。
- **競速房**：E1 房間選遊戲 `kart`；房主選賽道、模式（時間賽／道具賽）、圈數；等待室顯示每人選的車與角色（E10）；起跑倒數同步（伺服器 tick）；完賽順序與時間；結果畫面與再來一局。
- **觀戰與重播**：旁觀者可切換跟隨任一台車或自由視角；RoomDO 保存整場的 state 串流（壓縮）→ 重播器。
- **延遲實測**：兩台以上裝置、不同網路（家用、手機熱點）；記錄 RTT、插值緩衝、外推次數、主觀順暢度；寫進 `docs/KART-NETCODE.md`。

## 設計方向

- `RealtimeModule`（E2 `e2-t11`）落地：`onState`、`onEvent`、`authoritative(pickup|hit|lap|finish)`。
- RoomDO 不跑物理，但要有 `shared/kart/physics.ts` 做**合理性檢查**（速度不能超過最高速 ×1.5、位置跳躍過大就丟棄）——不是反作弊，是防 bug。
- 時間同步：連線時做三次 ping 估 offset；所有事件帶伺服器 tick。
- 粒子、音效在本機依事件播放。

## 風險與對策

| 風險 | 對策 |
| --- | --- |
| DO 每房 20 Hz × 8 人的訊息量 | 二進位、小封包；免費額度估算在 E12 成本；超出就降到 15 Hz |
| 插值讓道具命中「看起來」不公平 | 命中由伺服器用最後已知狀態裁定並廣播，接受小誤差；朋友圈可接受 |
| 客戶端自主模擬讓作弊變容易 | 非目標；合理性檢查擋 bug 不擋人 |

## 背景

第一款遊戲選陞官圖，理由：公有領域沒有版權顧慮；規則是「擲骰→看結果→移動」沒有決策，正好用來驗證 E2 的框架（回合、view、重連、結果）而不被規則拖住；而且中文圈的朋友都聽過。

## 目標

- M0：完整一局可玩：圖版、擲骰、依「德才功贓」移動官職、結算、再來一局；雙語介面。

## 非目標

- 歷史考據到每個朝代的官制（用一套簡化的清代官階即可，標明是簡化版）。
- 真錢或籌碼結算（只算名次）。

## 需求

- **規則（簡化版，寫在 `/games/promotion/rules`）**：每人從「白丁」起；輪流擲四面骰（德、才、功、贓）或四顆六面骰算出德才功贓；圖版每一格（官職）寫四種結果各往哪裡去；先到「榮歸」者勝，或限定回合數後比官階；「贓」會降職。
- **圖版資料**（`shared/games/promotion/board.ts`）：約 60–80 格，每格：id、名稱（zh-TW、en 音譯＋簡短說明）、品級、四種結果的目標格；資料自寫，標明為簡化版。
- **規則選項**：骰子種類（四面德才功贓／六面轉換表）、回合上限、人數 2–6。
- **畫面**：圖版用 SVG 自繪（方格環繞的傳統排法，但美術原創）；每人一個棋子顏色；輪到誰高亮；擲骰動畫；移動路徑動畫；側欄顯示每人目前官職與品級；手機版圖版可縮放。
- **結算**：名次、每人最終官職、擲骰次數；一句話評語（i18n）。

## 設計方向

- `GameModule<PromotionState, PromotionAction, PromotionView, PromotionOptions>`；action 只有 `roll`；`rng` 決定骰面；view 對所有人相同（沒有隱藏資訊），旁觀者也一樣。
- 圖版資料與畫面分離：`board.ts` 是純資料，`Board.tsx` 讀資料畫 SVG。
- 英文呈現：官職用音譯＋括號意譯（例如 "Zhuangyuan (Top Scholar)"），規則頁有一段「什麼是陞官圖」給外國朋友。

## C5 定案的細節

- **一屏怎麼算**（`src/games/promotion/useBoardFit.ts`）：量舞台在頁面上從哪裡開始、底下的 dock（輪到誰與擲骰那一條）有多高，舞台就拿「螢幕高度 − 上面 − dock」那麼高（至少 240 px）；舞台裡工具列以外剩下的盒子量出寬高，`fitBoard`（`boardLayout.ts`）算兩種排法各自能放多大，選大的那個，圖版用 px 寬度畫。螢幕高度用 `documentElement.clientHeight`，不用 `innerHeight`，手機網址列收放時圖版不會一直重算。房間版面在 900 px 跨過寬窄時會把遊戲搬到頁面上另一個位置，所以量的元素用 callback ref，搬家後量新的那個（第一版用 ref 物件，從 1440 縮到 390 時圖版寬度變成負數，是 Playwright 截圖抓到的）。
- **兩種排法**（`boardLayout.ts`）：**橫式**約 5:3，上排侍衛處｜翰林院｜中樞｜京師部院、下排綠營武職｜武科｜科舉｜地方官，每塊最多四列格子，窄的那排把格子拉寬對齊；**直式**約 3:5，左欄中樞、翰林院、京師部院、科舉（文官的路），右欄侍衛處、綠營武職、地方官、武科，短的那欄把格子拉高對齊。兩種都是武官在一邊、榮歸在上、科舉在下。**C4 的三欄（約 7:8）和手機一欄都拿掉了**：三欄在桌機橫螢幕上被高度卡住（1280 × 720 一格只剩約 33 px），手機一欄有三個多螢幕高，違反一屏；只有接近正方形的盒子三欄才比較大，那種螢幕少，又要多約 0.2 kB，預算放不下。外觀（朱漆金邊、宣紙、楷書、印章、頂戴、陀螺、棋子）都沒改。
- **量到的大小**（Playwright，Chromium）：1920 × 1080 一格約 89 px、1440 × 900 約 68 px、1280 × 720 約 46 px、390 × 844 直拿約 26 px（直式）、844 × 390 全螢幕約 50 px（橫式）。三種桌機尺寸與手機直拿，79 格整格都在畫面裡，擲骰鈕與輪到誰也在（`e2e/promotion-fit.spec.ts`）。
- **手機的決定**：直拿時**整張圖版縮在一個畫面裡**（直式排法，一格約 26 px，官名約 8–9 px：看得出誰在哪、哪格大哪格小，字要湊近看），不再一欄長捲。要看字有三條路：兩指縮放或 −／＋（原本就有），點格子開說明，或**轉橫再按全螢幕**（844 × 390 一格約 50 px、官名約 13 px）。直拿時舞台下面一行小字提示「字太小？轉橫再按全螢幕」（只在 600 px 以下直拿時出現，純 CSS，不能關；做成可關要記 localStorage，預算放不下）。手機橫拿但不全螢幕時，頂欄、標題、工具列與 dock 把高度吃光，圖版很小（舞台最少 240 px，整頁會超出一點），那時就是要按全螢幕。
- **小圖版**：一格畫出來不到 60 px 時（`dense`），官名放大 1.3 倍、置中用滿整格，品級印章只留紅色小塊不寫字（那時印章的字只有 3–4 px，本來就看不見）；品級仍看得出來：浮水印的大小、左上的頂戴、點開的說明。
- **全螢幕**（`useImmersive.ts`）：按鈕對圖版那一塊（座位籤、圖版、欄）呼叫 `requestFullscreen()`；沒有這個 API（iPhone）、被拒（iframe 沒有權限）或丟錯時，改成**專注模式**：同樣的版面用 `position: fixed` 蓋住頁面自己的頂欄與側欄。兩種模式版面相同：圖版佔滿，旁邊（直拿時是下面）一條欄放陀螺、輪到誰、上一擲、回合、擲骰、−／＋／還原、「離開全螢幕」。全螢幕時 dock 不給內容，頁面上永遠只有一個擲骰鈕。離開：「離開全螢幕」鈕或 Esc（真的全螢幕是瀏覽器自己的 Esc，頁面從 `fullscreenchange` 得知；專注模式是頁面聽 Esc）。**不記住**：瀏覽器每次進全螢幕都要使用者按一下，記住了也不能自動進，重新整理後頁面自己蓋住自己反而奇怪。沒有轉場動畫（減少動態時本來就不該有，預算也省下來）。
- **格子說明**改成點了才開的底部面板（共用的 `Drawer`，原生 `<dialog>`：焦點鎖在裡面、Esc 關、關了焦點回到那一格），不再固定佔在圖版下面，圖版預設不被任何東西蓋住。德才功贓去向的小印仍標在自己那格的去向上（點了別格就標那一格）。「簡化版」那句話移到說明面板最下面。點玩家籤也是開那個人那格的說明。
- **浮水印**（`rankArt.svg`、`rankArt.ts`）：線稿是 AI 協作者手寫的 SVG（由程式產生座標，沒有描任何圖），13 個 `<symbol>`（12 頂帽子加榮歸的牌坊），只用 `currentColor` 與 `var(--knob)`，沒有自己的顏色；格子用 `<use href="…/rankArt-<雜湊>.svg#official2">` 引用，顏色是 `promotionBoard.ink`、不透明度 0.22，在官名後面。是靜態檔（Vite 打包成有雜湊的資產，`?no-inline` 不內嵌成 data URL，Chrome 不接受 data URL 的外部 `<use>`），首次繪製後才由瀏覽器下載，**不算 JS 首屏**；約 18 kB、gzip 約 2 kB，登記在 `docs/ASSETS.md`。注意：XML 註解裡不能有 `--`（第一版因此整個檔解析失敗、什麼都沒畫），測試擋。分級（示意，取清代服飾大意）：

  | --- | --- | --- |
  | 布衣 | 白丁、童生、武童 | 瓜皮帽 |
  | 士子 | 生員、監生、貢生、舉人、貢士、庶吉士、武生、武舉 | 暖帽、素頂，後面一支毛筆 |
  | 科甲 | 狀元、榜眼、探花、進士、武狀元、武進士 | 暖帽兩側簪金花 |
  | 文官 | 未入流到正七品 | 涼帽、紅纓、頂戴 |
  | | 從六品到正四品 | 再加藍翎 |
  | | 從三品到正二品 | 改花翎（單眼） |
  | 最高 | 中樞四格、從一品以上的文官、領侍衛內大臣 | 最大的官帽、雙眼花翎、朝珠 |
  | 綠營 | 額外外委到千總／守備到參將／副將以上 | 頭盔與頂；加紅纓；再加花翎與鉚釘 |

- **玩家籤**上，名字後面一頂 26 px 的小帽子，是他目前那格的浮水印（不透明，顏色跟著文字、頂珠是品級色），一眼看出誰在哪個階段。棋子上**沒有**加：棋子只有 28 px，上面已有名字的首字，再加帽子會糊。
- **首屏預算**：陞官圖 148.5 → 150.0 kB（149,977 bytes，上限 150,000，**只剩約 20 bytes**）。為了放得下：(1) 試過把格子說明與它的字串改成 lazy 載入，打包器會把 Vite 的 preload helper 從入口拆成獨立 chunk，**每一條首屏都多約 0.4 kB**，陞官圖淨少 0.5 kB 還是超過、別人變大，所以沒做（NEXT 記過的同一個問題；從 `screens.ts` 或入口 import 也一樣或更糟）；(2) 拿掉 C4 的三欄排法；(3) 說明改用共用的 `Drawer`；(4) 全螢幕時沒有把頁面其他部分設成 `inert`（約 0.1 kB）：專注模式時鍵盤的 Tab 仍可能走到被蓋住的頁面元素；(5) 提示不能關。浮水印的線稿與榮歸的牌坊（原本是程式裡的一條 path）都放在 SVG 檔裡。**下一個動陞官圖首屏或共用外框的批次一定要先騰出空間。**
- **已知的缺口**：只在 Playwright（Chromium）的 1920、1440、1280、390、844 px 與預覽站看過，沒上實體手機，沒試過 iPhone Safari 的專注模式與 iPad 的真全螢幕。專注模式裡打開格子說明再按 Esc，會同時關掉說明並離開專注模式。兩指縮放的監聽綁在第一個圖版容器上，視窗跨過 900 px（例如平板轉向）之後要重新整理才又能兩指縮放（C2 就有的問題，按鈕縮放不受影響；修要約 30 bytes，預算不夠）。浮水印分級與服飾只是示意，沒有考據。

## 背景

第一款遊戲選陞官圖，理由：公有領域沒有版權顧慮；規則是「擲骰→看結果→移動」沒有決策，正好用來驗證 E2 的框架（回合、view、重連、結果）而不被規則拖住；而且中文圈的朋友都聽過。

## 目標

- M0：完整一局可玩：圖版、擲骰、依「德才功贓」移動官職、結算、再來一局；雙語介面。

## 非目標

- 歷史考據到每個朝代的官制（用一套簡化的清代官階即可，標明是簡化版）。
- 真錢或籌碼結算（只算名次）。

## 需求

- **規則（簡化版，寫在 `/games/promotion/rules`）**：每人從「白丁」起；輪流擲四面骰（德、才、功、贓）或四顆六面骰算出德才功贓；圖版每一格（官職）寫四種結果各往哪裡去；先到「榮歸」者勝，或限定回合數後比官階；「贓」會降職。
- **圖版資料**（`shared/games/promotion/board.ts`）：約 60–80 格，每格：id、名稱（zh-TW、en 音譯＋簡短說明）、品級、四種結果的目標格；資料自寫，標明為簡化版。
- **規則選項**：骰子種類（四面德才功贓／六面轉換表）、回合上限、人數 2–6。
- **畫面**：圖版用 SVG 自繪（方格環繞的傳統排法，但美術原創）；每人一個棋子顏色；輪到誰高亮；擲骰動畫；移動路徑動畫；側欄顯示每人目前官職與品級；手機版圖版可縮放。
- **結算**：名次、每人最終官職、擲骰次數；一句話評語（i18n）。

## 設計方向

- `GameModule<PromotionState, PromotionAction, PromotionView, PromotionOptions>`；action 只有 `roll`；`rng` 決定骰面；view 對所有人相同（沒有隱藏資訊），旁觀者也一樣。
- 圖版資料與畫面分離：`board.ts` 是純資料，`Board.tsx` 讀資料畫 SVG。
- 英文呈現：官職用音譯＋括號意譯（例如 "Zhuangyuan (Top Scholar)"），規則頁有一段「什麼是陞官圖」給外國朋友。

## C4 定案的細節

- **部門與排法**：部門歸屬是資料（`departments.ts`，每部門由高到低列出 id），`board.ts` 一個字都沒改，所以進行中的房間不受影響。寬螢幕（720 px 以上）是傳統的三欄：侍衛處｜中樞｜翰林院、綠營武職｜京師部院｜地方官、武科｜科舉｜地方官（地方官跨兩列）；兩側每列三格、中間四格，中樞的四個最高官職剛好一列，榮歸是上面一格金色大格。
- **手機排法（為什麼一欄）**：720 px 以下八個部門由上往下排成一欄（中樞與榮歸在最上、科舉在最下），每列四格，390 px 的手機上一格約 80 px 寬、官名約 17 px。代價是圖版很長（約三個多螢幕高），但不用左右捲，單指上下捲就是手機的習慣；寬版硬塞進 390 px 會小到看不清，或要左右捲。點上面的玩家籤會把他的格子捲進畫面。
- **字型**：LXGW WenKai TC（OFL）從 Google Fonts 載入，用 `text=` 只要圖版用到的 175 個漢字與拉丁字母（約 63 kB），不打包、不放 R2；登記在 `docs/ASSETS.md`。載入前或失敗時用系統楷書，再退到襯線字。
- **英文格子**只放音譯（"Juren"），括號意譯在格子說明裡；品級印章在英文是短標籤（"Jr 7"、"Sr 1"、"Exam"、"Unranked"、"None"），完整品級也在說明裡。
- **頂戴**：一品紅寶石、二品珊瑚、三品藍寶石、四品青金石、五品水晶、六品硨磲、七品素金、八九品鏤花金，未入流與未仕沒有。只是示意：格子說明寫「頂戴（示意）」。
- **預設說明的格子**改成自己所在的格子（旁觀者是輪到的人那一格），德才功贓的去向標記就是這一格的；點別的格子看別的。
- **顏色**：圖版的顏色是 `tokens.ts` 的 `promotionBoard`，深淺色相同，是一般值不是 CSS 變數（SVG 屬性讀不到 CSS 變數）。
- **陀螺**：一次擲骰轉四圈以上，在 `ROLL_MS`（由 900 改成 1100 ms）內減速停到擲出的面，轉的時候有一點晃；只有房間真的有新的一擲才轉，重新連線或減少動態效果時直接停在那一面。
- **首屏預算**：重畫讓陞官圖的畫面 chunk 多了約 4 kB，原本只剩 3 kB 的預算不夠；把 QR code 的編碼器（`qrcode-generator`）改成等待室要畫的時候才載入，房間頁少約 7 kB，兩款遊戲的首屏都變小。
